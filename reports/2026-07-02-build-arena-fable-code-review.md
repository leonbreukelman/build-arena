## TOP_FINDINGS

1. **HIGH — Dream lane spends on live APIs with no `--allow-live` gate.** `arena/dream_generate.py:53-63` and `arena/dream_research.py:53-63` go live whenever `--live-model` is set; neither CLI, nor the `arena/dream_run.py` orchestrator (`_build_parser`, ~line 350; `_live_stage_flags` at 201-205), exposes an `--allow-live` flag. The policy requires *both* flags. `arena/proposal_run.py` shares the pattern: its own CLI has no `--allow-live`, and it hard-passes `--allow-live` to the rerank stage (`proposal_run.py:274`) — intent is implied by running the command rather than explicitly acknowledged. **Fix:** add a required `--allow-live` to `dream_generate`, `dream_research`, `dream_run` (and decide whether `proposal run` should carry one, since its judge call is unavoidable), mirroring `project_model_cli.py:65-70`. Test: live invocation without the flag exits non-zero with no client constructed.

2. **HIGH — Served-model mismatch fails open at 3 of 4 live call sites.** `require_served_model_match` defaults to `False` (`arena/llm_adapter.py:158`, enforced only at 207-213). Only `arena/project_model_llm.py:77` opts in; `dream_generate.py:63`, `dream_research.py:63`, and `proposal_pairwise_reranker.py:207` accept whatever model the provider serves, recording the mismatch in metadata only. Additionally, `served_model = str(packet.get("model") or self.config.model)` (`llm_adapter.py:207`) treats a *missing* served-model field as a match even under strict mode. **Fix:** pass `require_served_model_match=True` at all three sites; under strict mode treat an absent `model` field as a mismatch. Test: per-lane mismatch tests mirroring `test_llm_adapter.py`'s strict-mode test.

3. **HIGH — The freshness machinery is opt-in and self-referential, so stale project models pass.** (a) The gate's `snapshot_freshness` check runs only `if snapshot_obj.graph_hash:` (`arena/project_model_gate.py:63-66`), and `graph_hash` defaults to `""` (`arena/project_snapshot.py:110`) — the gate's own passing fixture uses `graph_hash=""` (`tests/test_project_snapshot_gate.py:79`), so the branch never fires on the default shape. (b) `arena/project_model_v1.py:47` backfills an empty hash from the *current* graph, guaranteeing agreement. (c) `assess_project_model_freshness` compares `snapshot.graph_hash` to `projectGraph.graphHash` read from the *same file* (`arena/project_model_freshness.py:64-65, 263`) and never recomputes anything from disk; its only real-world coupling is `git rev-parse HEAD` + dirty check. A model built against an older tree state reports `fresh` / `safeForMutation=True`. Also, `ahead`/`behind` are computed (`:197-208`) but never influence status. **Fix:** make `graph_hash` mandatory (violation when absent), recompute the graph hash from disk in both gate and freshness, stop backfilling in `project_model_v1`, and fold `behind > 0` into a non-fresh status.

4. **HIGH — Proposal planner consumes scorecard/snapshot with no lineage or freshness enforcement; the guard built for this is dead code.** `arena/proposal_planner.py:130-205` re-reads the snapshot by path with no hash check against `scorecard["snapshotHash"]`, never compares `scorecard["repoHead"]` to current HEAD, and never calls freshness. `ProposalRegistry.check_lineage` (`arena/proposal_registry.py:193`) has exactly one caller — a test (`tests/test_proposal_registry.py:113`). `capture_git_lineage` stamps *current* HEAD, so a plan built from a commit-A scorecard at commit B claims commit-B lineage. Fresh-workdir `proposal run` invocations are safe by construction; standalone stage invocations are not. **Fix:** wire `check_lineage`/freshness into `build_proposal_plan_with_registry` and refuse stale inputs.

5. **MEDIUM — Reranker default judge silently uses a hard-coded paid default model.** `DefaultLLMProposalJudge.create()` calls `resolve_provider_config("xai")` without `require_explicit_model=True` (`arena/proposal_pairwise_reranker.py:204-207`), falling through to `grok-4.20-0309-non-reasoning` (`llm_adapter.py:119`). The reranker CLI has no `--live-model` flag, so `python -m arena.proposal_pairwise_reranker ... --allow-live` with a key but no `BUILD_ARENA_LLM_MODEL` spends on an implicit model — violating "explicit `--live-model`". (Via `proposal run` the env is threaded and preflighted, so that path is safe.) **Fix:** `require_explicit_model=True` in `create()`.

6. **MEDIUM (latent) — No post-apply changed-file boundary re-check.** The boundary is enforced pre-apply on *declared* `target_files` only (`arena/loop.py:111-119`; `arena/boundary.py:36-63`). Nothing re-validates the actual diff after a runner applies: `CandidatePackager` rejects only `.arena/` staged paths (`arena/worktrees.py:127-131`), and `GitPromoter` does `git add -A` with no filtering (`worktrees.py:84`). An adapter writing outside its declared targets could land changes in `scorer/`/`verifier/`/`schema/`/`arena/generated/`. Latent — the loop has no production entrypoint — but this is the enforcement gap that matters the moment it's wired. **Fix:** post-apply `git diff --name-only` re-checked through `is_boundary_violation` + sensitive-prefix rejects in both packager and promoter.

7. **MEDIUM (latent) — Deterministic ablation stand-in is a hard gate under the shipped config, contradicting the "coherence check only" posture.** `ablation_advisory` defaults `False` (`verifier/config.py:21, 47`) and `.arena/config.toml` doesn't set it, so `verifier/engine.py:135-136` turns the keyword-matching stand-in (`verifier/ablation.py:55-58` — any reasoning containing "because"/"tests" passes) into a promote/discard input in `loop.py:158-159`. Latent (loop is test-only), but the default is fail-open in the semantic sense: a gameable PASS is consumed as verification. **Fix:** flip the default / set `ablation_advisory = true` in the shipped config; keep the result advisory-only in the verdict.

8. **MEDIUM — Schema→generated drift is unverified in CI.** `.github/workflows/ci.yml` runs only ruff/pyright/pytest; `make generated-fresh` exists but is unwired, and `tests/test_schema_generation.py:8-19` checks existence/importability only. A hand-edit to `arena/generated/models.py` diverging from `schema/arena.yaml` passes CI. Relatedly, the scorer lock pins `scorer/**/*.py` only (`scorer/lock.py:26-34`); `verifier/`, `schema/`, `arena/generated/` have no integrity pin anywhere. **Fix:** add `make generated-fresh` (or an equivalent regenerate-and-diff pytest) plus a lock-freshness check to CI; consider extending lock coverage.

9. **MEDIUM — A zero credits cap is silently ignored (fail-open).** `arena/budget.py:49-56`: `cap == 0` on `*_credits` is skipped entirely, so an operator expressing "no spend" as `claude_code_credits_cap=0` gets unlimited credits, while `0` on wall-clock/cycle caps breaches immediately — inconsistent semantics, untested (`tests/test_budget.py` never tests 0). **Fix:** treat `None` as unlimited and `0` as a real cap, with a test.

10. **MEDIUM — `proposal run --keep-workdir` is a no-op.** `_config_from_args` never passes `keep_workdir=args.keep_workdir` (`arena/proposal_run.py:361-373`; field defined at 75, honored at 325-330), so successful runs always delete the temp workdir. `dream_run.py` wires it correctly — an instance of the ~90% driver duplication between the two files drifting. **Fix:** one-line wiring fix + a `main()`-level test; consider extracting the shared stage-driver scaffolding.

11. **MEDIUM (interpretive) — `arena.package_pr` can push a branch and open a PR on a target remote.** `arena/pr_packager.py:84-103`, reachable only with explicit `--open-pr --allow-gh`, dry-run default, self-remote refusal, never merges (tested at `test_pr_packaging.py:208`). Whether "push candidate branch + open PR" counts as prohibited mutation or sanctioned proposal delivery is an operator policy call — the code treats it as the delivery seam and gates it well. Recommend an explicit decision documented, plus a test asserting no push to a default branch is possible.

12. **LOW (latent) — `.arena/goal.toml` is not boundary-protected but drives scorer command execution.** `scorer/engine.py:107, 141-155` executes the worktree's goal-config commands; `arena/boundary.py:16-23` protects only `.arena/scorer.lock.toml`. A patch editing `goal.toml` could rewrite scoring commands/weights before scoring. Latent (loop-only) — add `.arena/` to the protected set or load goal config from the host.

Minor (noted, not blocking): `_dream_count` swallows read errors → stale `gated-dreams.json` in a reused `--workdir` can misreport a gate crash as "no dream" (`dream_run.py:311-317`); failure-ledger fingerprints are path-scoped, not commit/content-scoped, permanently blocking retries after files change (`arena/fingerprints.py:48-78` vs commit-scoped `proposal_key_for`); `proposal_ranker.py` is a dead parallel ranker drifting from the live pipeline; `resolve_api_key_with_source` silently picks up keys from `~/.hermes/.env` (documented, but implicit); `events.py:128-142` projection currency check is count/max_seq-only (impact bounded — sqlite is documented non-authoritative and no consumer reads it as truth).
